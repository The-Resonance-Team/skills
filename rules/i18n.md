# i18n Rules — projects with message catalogs

Applies to any repo with an i18n feature: message catalogs (`{vi,en}` per namespace), multi-locale UI, locale-aware translators (next-intl, custom `useI18n`). Consumers WITHOUT i18n must omit this file. Includes this file for any repo that ships user-facing strings through a catalog.

## Scope

Catalog discipline: where strings live, locale parity, interpolation limits, what is deliberately NOT translated, and which words a message may use.

## Catalog ownership (mandatory)

1. **Every UI string lives in the catalog** — messages live in `packages/i18n/src/messages/{vi,en}/<ns>.json` (one file per namespace per locale, merged at a shared `locales.ts`). Components use the app translator (`useTranslations` on next-intl apps, `useI18n()` on the miniapp) and render `t('<ns>.key')`. A hardcoded string in a file that already calls `t()` is still a violation — sweep stragglers, not just files with no translator. When converting, reuse existing keys before adding new ones; never ship a second key for the same string.

2. **en ≡ vi parity is a build rule** — every new key goes into BOTH locale files in the same commit. A parity test (en ≡ vi key sets) guards it; missing keys return the key itself at runtime, so a bare key is a typo signal, not a fallback.

3. **Interpolation only, no rich text** — the miniapp translator substitutes `{name}` placeholders only; it does not render markup. For emphasis inside a message, split the message so the styled segment arrives as a param value and wrap the param in JSX: `t('court.cancelFree', { days: '≥ 2 ngày' })` rendered inside `<b>{days}</b>`. Next-intl apps may use `t.rich` where the message needs inline markup.

4. **Label maps hold keys, not strings** — when display labels live in a data/constant map (`AMENITY`, `BOOKING_STATUS`, status/sort enums), the map stores i18n keys (`'courtList.amenityLight'`), never user-facing text, and the render site calls `t(label as I18nKey)` (the typed key union). Translation happens at the render boundary, not inside data.

5. **Not everything is chrome** — do not translate: content (articles, wiki, help pages), demo/mock data, proper nouns (venue names, zones, cities, person names), locale labels (`Tiếng Việt`), currency suffixes (`đ`) and other formatting (use the shared `vnd()`/`VND()` formatters), and strings embedded in API payloads (`desc` fields) — those are data, not UI. Dead label maps with no consumers are not an i18n gap; fix or delete them, don't translate them.

6. **Never pass a possibly-undefined key to the translator** — `t(key)` throws deep inside the translator implementation when `key` is `undefined` — not a graceful no-op, not a caught React error, a crash. A fallback chain (`a?.b ?? c?.d`) that can bottom out at `undefined` must resolve to a real key before it reaches `t()`:

   ```ts
   // Bad — throws when both sides are unset
   tr(FORMATS[x]?.label ?? x);

   // Good — always resolves to a real key
   tr(FORMATS[x]?.label ?? "fallback.key");
   ```

   Proven by a real incident: `tr((FORMATS[t.stageTwo?.format || '']?.label ?? t.stageTwo?.format) as I18nKey)` crashed the whole screen whenever `t.stageTwo` was `null` (a field that was, in practice, never populated) — the `??` chain bottomed out at `undefined`, not a string.

## User-facing copy (mandatory)

Rules for writing or rewriting message values. A copy pass edits values only: keys and every `{placeholder}` stay intact. Dead keys stay dead — delete them or leave them, re-polishing them only launders copy nobody renders.

7. **A message names the outcome and the next step, never the machinery** — users read what happened and what to do ("Đang xác nhận thanh toán, tự cập nhật trong vài giây"), in their own words. Internal vocabulary stays out of every message value: integration names and mechanics (webhook, HMAC, VA, memo, feed), process codes (SLA, SOP, RLS, WORM, CAS, k-anonymity), and raw enums or status codes. A provider name earns its place only where the user acts inside that provider's own UI (e.g. "dán vào mục Webhooks của SePay").

8. **One term table per product** — the repo glossary (`GLOSSARY.md`) carries a User-Facing Copy section mapping each internal term to its displayed VI and EN form (e.g. Paddle DNA → "Gu vợt", Price Bank → "Giá tham khảo", Match Score → "Độ hợp {n}%"). Write from the table; add a new display term to the table in the same change that uses it. A string that contradicts the table is a violation even when it reads well.

9. **VI leads, EN mirrors** — draft the VI value first, then mirror `en` in the same commit (rule 2). Keep English only for brand/product names and sport or industry terms with no common VI equivalent (dink, kitchen, sweet spot); give each a short VI gloss at first use ("vùng bếp (kitchen)"). One term, one translation, everywhere: a term rendered three different ways across files is one drift bug, not three wordings.

10. **A translated label stands alone** — no code, enum, or English original parked in parentheses beside it. "Đủ đôi (PAIRED)", "Trạng thái: PENDING_PAYMENT", "409 · SCHEDULE_CONFLICT" are leaks of the internal name; the machine value lives in the key or the payload, the label holds the human reading.

11. **Policy numbers live once** — refund, cancel, and cutoff copy states its days and percentages from a single source, and every surface repeating the policy repeats the same numbers. Two keys disagreeing ("hủy trước 4 giờ" vs "≥ 2 ngày") is a bug to fix at the source, not a wording choice.

12. **Error catalogs are sentences** — each `errors.json` value tells the result and the next step in the user's language ("Khung giờ này đã đầy, chọn khung khác nhé"); the error code does its work as the key only.

13. **Server-sent copy follows the same rules** — strings that reach users through API payloads (quiz questions, challenge and tier names, notification templates, seed data) are user-facing copy living outside the catalog, and a catalog-only pass misses them. Widen any copy audit or rewrite to seed files, template constants, and hardcoded data modules, not just `messages/`.

14. **A sweep closes the rewrite** — the change is done when a grep over the touched catalogs returns nothing: the internal terms from rule 7 plus the banned internal names of the product's own term table. Extend the sweep over the e2e spec corpus — specs that assert literal copy strings break on the rename (`rules/e2e-testing.md` rule 17). Wire the sweep as a test case in the parity suite so CI keeps it green — the list grows with each leak found in review.
